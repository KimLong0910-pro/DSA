# Bài 23. Nhiều truy vấn đường đi ngắn nhất

## Bài toán

Cho nhiều truy vấn dạng:

```text
(s, t)
```

Mỗi truy vấn yêu cầu tìm đường đi ngắn nhất từ đỉnh `s` đến đỉnh `t`.

Ví dụ:

```text
Q = 100000 truy vấn
```

Cần chọn chiến lược phù hợp để tối ưu thời gian.

# Cách 1: Chạy Dijkstra cho mỗi truy vấn

Với mỗi truy vấn `(s, t)`:

```text
Run Dijkstra(s)
→ lấy dist[t]
```

## Độ phức tạp

Mỗi truy vấn:

```text
O((V + E) log V)
```

Tổng:

```text
O(Q × (V + E) log V)
```

## Ưu điểm

* Đơn giản
* Không tốn bộ nhớ thêm

## Nhược điểm

* Chậm nếu Q lớn

## Khi nào dùng?

* Số truy vấn ít
* Source thay đổi liên tục

# Cách 2: Tiền xử lý theo nguồn

Nếu nhiều truy vấn có cùng nguồn:

Ví dụ:

```text
(0,4)
(0,5)
(0,7)
```

Chỉ cần chạy Dijkstra một lần từ nguồn `0`.

## Độ phức tạp

Tiền xử lý:

```text
O((V + E) log V)
```

Mỗi truy vấn:

```text
O(1)
```

Tổng:

```text
O((V + E) log V + Q)
```

## Ưu điểm

* Rất nhanh khi nhiều query cùng source

## Nhược điểm

* Tốn bộ nhớ lưu dist

## Khi nào dùng?

* Nhiều query chung source

# Cách 3: All-Pairs Shortest Path

Tiền xử lý khoảng cách giữa mọi cặp đỉnh.

Có thể dùng:

* Floyd-Warshall
* Dijkstra từ mọi đỉnh

## Độ phức tạp

Floyd-Warshall:

```text
O(V³)
```

Bộ nhớ:

```text
O(V²)
```

Mỗi truy vấn:

```text
O(1)
```

## Ưu điểm

* Query cực nhanh

## Nhược điểm

* Tốn thời gian và bộ nhớ

## Khi nào dùng?

* Đồ thị nhỏ
* Số query cực lớn

# So sánh

| Chiến lược         | Preprocessing | Query        | Bộ nhớ     |
| ------------------ | ------------- | ------------ | ---------- |
| Dijkstra mỗi query | 0             | O((V+E)logV) | thấp       |
| Theo source        | O((V+E)logV)  | O(1)         | trung bình |
| All-pairs          | O(V³)         | O(1)         | O(V²)      |

# Kết luận:

* Query ít → Dijkstra mỗi lần
* Nhiều query cùng source → preprocess theo source
* Query cực nhiều → all-pairs shortest path
