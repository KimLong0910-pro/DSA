# Bài 5. Vì sao chọn m là số nguyên tố

## 1. Bài toán

Trong nhiều hàm băm, ta thường thấy:

```text id="p1"
h(k) = k mod m
```

Trong đó:

* `k` = key
* `m` = số bucket

Câu hỏi:

* Vì sao thường chọn `m` là số nguyên tố?
* Vì sao nên tránh kích thước là lũy thừa của 2?

## 2. Vấn đề nếu m là lũy thừa của 2

Ví dụ:

```text id="p2"
m = 16
```

Khi đó:

```text id="p3"
h(k) = k mod 16
```

Chỉ phụ thuộc mạnh vào các bit thấp.

Nếu dữ liệu có quy luật:

* 16
* 32
* 48
* 64

Thì:

```python id="p4"
keys = [16, 32, 48, 64]

for k in keys:
    print(k % 16)
```

### Output

```python id="p5"
0
0
0
0
```

Toàn bộ rơi vào cùng bucket.

→ Collision rất cao.

## 3. Nếu m là số nguyên tố

Ví dụ:

```text id="p6"
m = 17
```

Ta thử lại:

```python id="p7"
keys = [16, 32, 48, 64]

for k in keys:
    print(k % 17)
```

### Output

```python id="p8"
16
15
14
13
```

Phân bố đều hơn.

## 4. Vì sao số nguyên tố tốt hơn?

Số nguyên tố giúp:

* giảm pattern lặp
* giảm ảnh hưởng của quy luật dữ liệu
* phân phối bucket đều hơn

Đặc biệt tốt khi:

* dữ liệu có bội số
* dữ liệu tuần hoàn
* key có cấu trúc

## 5. So sánh thực nghiệm

Ví dụ:

```python id="p9"
keys = [16, 32, 48, 64, 80, 96]

print("m = 16")
for k in keys:
    print(k % 16, end=" ")

print("\n")

print("m = 17")
for k in keys:
    print(k % 17, end=" ")
```

### Output

```python id="p10"
m = 16
0 0 0 0 0 0

m = 17
16 15 14 13 12 11
```

## 6. Kết luận

### Chọn m là số nguyên tố giúp:

* giảm collision
* tăng phân bố đều
* cải thiện hiệu năng Hash Table

### Tránh:

* lũy thừa của 2
* các số có nhiều ước nhỏ
